Background Agents That Won't Get You Fired

Full 60-minute speaker script. Bracketed text is stage direction; quoted text is meant to be said close to verbatim. Running clock in the left margin of each heading.

Before the room fills

Run this the night before and the morning of. Live demos die from stale tokens, not bad code.

cd background-agents-workshop
claude --version && arcade --version && ngrok version && jq --version
arcade logout && arcade login          # token expires inside the hour — do this last
arcade whoami
grep -c "YOUR_KEY_HERE\|your_ngrok" .env
cd buggy-api && python3 -m pytest -q; cd ..   # MUST fail
./audit-check.sh clear && rm -f /tmp/arcade-demo-*.txt

Confirm Gmail, Linear, GitHub, Slack and Daytona are all connected for your Arcade user, the DEMO team exists in Linear with a Bug label, and the Gmail SearchThreads schema patch is in place — subject must be passed as an array. Without that patch the poller silently matches nothing and the demo never fires. Have the recorded run open in a background tab.

0:00–0:10 — Cold open: install, then first win (10 min)

[No slides. Screen shows their machines, not yours.]

"Before I show you anything, connect Arcade to whatever client you already have open. Then ask that client what tools it can now reach, and have it send you a Slack message."

[Put the config on screen. Each person needs their own key and their own user id — the per-user header is the entire point, not boilerplate.]

{
  "mcpServers": {
    "arcade": {
      "type": "http",
      "url": "https://api.arcade.dev/mcp/<their-gateway-slug>",
      "headers": {
        "Authorization": "Bearer arc_proj_THEIR_OWN_KEY",
        "Arcade-User-Id": "them@their-company.com"
      }
    }
  }
}

[Install first, ask second. A client that hasn't connected can only guess what Arcade is, and thirty different guesses is a bad opening minute. A connected one answers from its own tool list.]

[At minute 8, whatever the state of the room, land the turn. Everything after this hangs off it.]

"You just gave a model authenticated reach into your real accounts. It acted as you — not as a bot token with a shared password. Nothing in that config constrains what it does next. Right now you're watching it. The rest of this hour is about the hour when you're not."

Hard time-box at 10 minutes. Expect a third of the room to fail — corp laptops, no MCP-capable client, no Claude plan, VPN eating the OAuth callback. Fallbacks in order: pair up with someone who got in, or send them to the local track, which needs no account at all. Nobody sits blocked.

Do not hand out your own key to unblock people. One identity shared across a room means they are all acting as you, in your workspaces — and the audit trail you're about to show them will say so.

0:10–0:13 — Act 0: The claim (3 min)

[No terminal. One slide, or just the whiteboard. Trimmed hard, because the cold open already made this point on their own laptops.]

"Background agents run on a schedule or a trigger. Nobody is there to click approve. In a few minutes you'll watch one fix a bug end to end, and the interesting part is not that it can. It's everything that stops it from doing anything else."

[Draw three boxes. Leave them up for the rest of the hour and point at them as each one shows up.]

  1. Trigger — you own this. Today it's an email poller. Tomorrow it's cron, a webhook, CI, Inngest. Arcade does not wake your agent up.
  2. Procedure — a skill, not an agent. A markdown file the harness loads.
  3. Governance — the gateway: delegated per-user auth, policy checked at the moment of every action, and an audit trail.

0:13–0:23 — Act 1: Show the pieces (10 min)

"Everything fits on screen. That's the point."

ls

[Walk exactly three files, in this order. Resist opening a fourth.]

cat .claude/skills/support-triage/SKILL.md

"This is the agent. All of it. A numbered procedure with governance notes. The harness is Claude Code, unmodified. If we switch to Cursor next quarter, this file comes with us."

cat cate-config.yaml

"This is the policy. Three rules, three flavors of governance. Sandbox creation is blocked pending a human — that's stop. Pushes to main are blocked always — that's constrain. Every PR is forced into draft — that's stamp. The agent cannot opt out of any of them, because they run gateway-side, not agent-side. It's not a prompt asking it nicely."

cat buggy-api/src/handler.py     # the off-by-one lives in get_page()
cd buggy-api && python3 -m pytest -q; cd ..

"And this is the victim: a real repo with a real failing test. Two failed, one passed."

0:23–0:38 — Act 2: Fire the trigger (15 min)

./run.sh

[Then send the email from your phone, held up on camera, from the audience's point of view. Subject buggy api, body describing the pagination bug. Or ./trigger-email.sh if the room is remote.]

[Now narrate the terminal. Four beats:]

1. The poller sees the email and launches claude with a three-line prompt that names the skill and hands over the email body. Say the line: "the skill does the rest."

2. The agent files the Linear ticket. Point at the attribution on the ticket. "It acted as me, through my OAuth grant. Not as a bot token that everyone on the team shares the password to."

3. The agent asks Daytona for a sandbox — and hits the wall.

HITL_CHECKPOINT: Sandbox creation requires human approval.

[Stop dead here. This is the money beat. Say nothing for a beat and let the room read the agent's own explanation of why it's blocked and that it's waiting. Do not talk over it.]

"The deny is a message the agent can read. It knows why it stopped, it knows what it's waiting for, and nothing crashed — no exception, no half-finished state. And notice what the approval is: not a click inside our app. It's an out-of-band change to policy, made by someone who isn't the agent."

4. The watcher auto-approves after 30 seconds — or run ./hitl-approve.sh yourself for effect. The agent retries the same call and proceeds.

0:38–0:48 — Act 3: Watch it work (10 min)

[Mostly narration while the agent runs. Call these out as they scroll past; don't read the log aloud.]

  • Clone into the sandbox. Git identity set from Github.WhoAmI — attribution again, now on the commit itself.
  • Failing test reproduced first, then the fix applied. Tests green.
  • Branch fix/buggy-api-<timestamp> pushed. If anyone asks "what if it pushed to main" — it can't. Offer to prove it in Q&A by asking the agent to try, live.
  • PR opens as a draft it never asked for. Show it in the browser. Policy stamped it on the way out.
  • Ticket moves to In Review. Slack summary lands in #demo-engineering.

0:48–0:55 — Act 4: The receipts (7 min)

"The demo isn't the PR. The demo is the audit trail."

./audit-check.sh logs

"Every tool call, every input, every policy decision — attributable to the human the agent acted for. In production this streams to your SIEM over OpenTelemetry. An agent running while you sleep is as accountable as one you're watching over the shoulder."

[Then the live policy change. This is the beat that lands hardest with security people.]

./hitl-approve.sh --restore     # re-block sandbox creation

"Policy is evaluated at the moment of action, not at setup. Revoke a user, downgrade a role, change a rule — the running agent feels it on its next call. Nothing to redeploy, nothing to restart."

[Cut the second bug email. That's where these seven minutes come from. State the effect; don't spend four minutes re-running the loop to show it.]

0:55–1:00 — Act 5: What you'd take home (5 min)

[Point back at the three boxes on the whiteboard, in order.]

  • The trigger was 100 lines of bash. Replace it with whatever fires in your stack. Arcade's job starts at the first tool call.
  • The agent was a markdown file. Version it, review it, ship it like code.
  • The governance was config. No changes to the tools, no changes to the agent, no SDK in your way.

Closer: "The runtime is a commodity. What's scarce is authenticated tools, reusable procedures, and the governance that lets an agent run with nobody watching."

[Land the closer here, right after the audit trail — not after the PR. The PR proves a capability they already believe in. The audit trail proves accountability they currently cannot produce.]

Q&A prompts that reliably work: "What if the agent edits the test instead of the code?" — the skill forbids it, PR review catches it, the audit log proves it. And "why not just a service account?" — walk the delegated-auth section of the README.

Alternate second half: hands-on track (30 min, no accounts)

If the room skews hands-on, drop Acts 3 and 5 and run this instead. It needs only git, go and python3 — it's the only part thirty laptops can reliably do at once.

1. Clone and reproduce (5 min)

git clone https://github.com/arcadeai-labs/daytona-background-agents
cd daytona-background-agents/buggy-api
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python -m pytest -q        # 2 failed, 1 passed — the bug is real
cd ..

2. Run the policy server and get told no (10 min)

cd cate-server && go build -o cate-server . && ./cate-server -config ../cate-config.yaml -port 8888 &
cd ..
curl -s -X POST localhost:8888/pre -H 'Content-Type: application/json' -d '{
  "execution_id":"me-1",
  "tool":{"name":"CreateSandbox","toolkit":"Daytona"},
  "inputs":{"name":"triage"},
  "context":{"user_id":"you@example.com"},"servers":{}
}'
# -> {"code":"CHECK_FAILED","error_message":"HITL_CHECKPOINT: ..."}

Have them try the other two rules: GitPush with "branch":"main" (blocked) versus a feature branch (fine), and CreatePullRequest (allowed — but look at the override in the response, draft: true got injected).

3. Be the human in the loop (5 min)

./hitl-approve.sh            # flip the rule, re-run the CreateSandbox curl -> OK
./hitl-approve.sh --restore  # put the wall back, re-run -> blocked again

4. Read the receipts (5 min) — ./audit-check.sh logs shows every request they just made, with the decision attached.

5. Loop and graph engineering (10 min) — both run on a bare python3, no credentials, no network.

python3 examples/loop_engineering.py --stuck          # loop escalates instead of spinning
python3 examples/graph_engineering.py --skip-review   # denied edge prunes the subtree

Stop on the loop example's first iteration: the model proposes weakening a test assertion and the harness refuses. That's SKILL.md step 6 moved out of the prompt, where the agent can't argue with it. The graph example's EDGE_POLICY is the same idea one level up — policy on a handoff between agents rather than on a single tool call.

Debrief: "Everything you just did with curl is exactly what the agent experienced in the live demo. Governance lives in the gateway, so it doesn't matter whether the caller is a model or a human with curl. Same rules, same denials, same audit trail."

Contingencies

FailureRecovery
Arcade token expired mid-demoarcade logout && arcade login, restart run.sh. Pre-flight catches this — the token expires inside the hour.
Gmail poller sees nothingCheck the WATCH_SENDER filter and the buggy api subject; send from the allowed address. Confirm the SearchThreads array-subject patch is applied.
Agent skips the skillThe poller prompt names it explicitly. If it still free-styles, restart, blame the demo gods, and show SKILL.md as the artifact instead.
HITL approval doesn't fireRun ./hitl-approve.sh manually. The watcher is a convenience, not the mechanism.
Daytona sandbox slow to startNarrate ./audit-check.sh logs while waiting. It's the better content anyway.
Wifi diesThe recorded run. Always have the recorded run.
